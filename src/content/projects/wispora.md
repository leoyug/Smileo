Wispora 是一个面向设计与开发工作的个人网络灵感库。我可以把网站、文章和想持续关注的作者添加进来，通过封面、描述、标签和本地搜索，在需要时重新找到它们。它使用 WXT、React 和 TypeScript 构建，数据保存在当前浏览器中，无需注册账户，也不依赖独立后端。

## 为什么要做

在做设计和开发时，我经常遇到想留到以后再用的内容：一个排版漂亮的网站、一篇解释清楚技术细节的文章，或者一个值得持续关注的作者。把链接保存下来很容易，但过一段时间，我往往只记得它大概能解决什么问题，已经想不起名字，也不知道当时放在了哪里。

我想做一个适合自己工作方式的工具。添加时尽量简单，不必先想好完整的分类；回来看时，又能通过图片和文字认出内容，再逐步缩小范围。评价它是否有用的标准也很具体：面对一个设计或开发需求，我能不能在一分钟内找到之前保存过、现在用得上的东西。

这也是一个整理自己审美和知识积累的过程。把零散的内容放在一起，重新浏览时，才容易发现自己反复关注的主题，以及那些保存之后一直没有真正用起来的东西。

## 关于这个应用

我把 Wispora 做成了浏览器扩展。大多数内容都是在浏览网页时遇到的，添加入口放在浏览器里更顺手。点击工具栏图标，就能在当前网页上打开快速添加面板；需要整理和查找时，再进入完整的工作台。

内容分成网站、文章和关注源三种类型，分别突出不同的信息。网站更依赖封面和描述，文章更看重标题与来源，关注源则需要让人快速认出作者。主题、风格、技术和用途交给标签表达，避免把所有维度塞进一套越来越复杂的分类里。经常使用的范围和标签组合，还可以保存成侧栏里的快捷视图。

工作台提供详情卡片、紧凑卡片、详情列表和紧凑列表四种排列。想浏览视觉参考时可以看封面，需要快速扫描大量内容时可以切换列表。打开详情后能直接编辑标题、描述、标签和封面，返回时保留之前的搜索和浏览位置。

技术上，业务数据通过 Dexie 保存在 IndexedDB 中，界面偏好和少量配置使用浏览器扩展存储。正文提取使用 Readability，再经过 DOMPurify 清理，保存为可阅读的本地快照。搜索由 MiniSearch 完成，覆盖标题、描述、域名、标签和已经保存的正文，不需要等待 AI 返回结果。

AI 是可选的整理助手。配置自己的 API Key 后，它可以帮助补全描述和生成标签，但链接会先保存，整理在后台继续进行。描述优先使用用户填写的内容，其次是网页自带描述，最后才由 AI 补充；手动调整过的信息也不会被后续自动处理覆盖。即使没有配置 AI，添加、编辑和搜索依然可以使用。

视觉上，我希望它适合长时间浏览，所以使用了暖灰色背景、紧凑的排版和少量品牌橙色。设计系统把颜色、字体、圆角和交互状态统一收进语义 token，共享组件以 Intent UI 和 React Aria 为基础。Figma 和浏览器之间的颜色一致性也做了专门处理，以 Display-P3 为权威值，同时保留 sRGB 回退。

目前项目是 v0.7.3，核心本地流程已经接通，也加入了备份恢复和内容简报。今日总结与一周简报只使用本地已保存的信息，生成后保留当时的内容，方便重新阅读。完整的 Chrome / Edge 扩展发布验收仍在后续计划中。

## 遇到的挑战

这个项目比较难的地方，是让添加过程足够轻，同时保证后续处理可靠。网页可能读不到正文，封面可能缺失，AI 也可能超时。如果把这些步骤都放在保存之前，一次普通的添加就会变得缓慢而脆弱。

因此我把流程拆成了先保存、再补全。最基本的链接、类型和时间先进入数据库，其他信息逐步补齐。浏览器扩展的后台进程随时可能被停止，所以重要任务和状态也必须先持久化，不能只存在内存里。这些细节平时不显眼，却决定了用户关闭页面、重启浏览器之后，内容是否还在，任务是否还能继续。

快速添加面板也经历了一次结构调整。最初使用浏览器原生弹窗，但标签候选列表会被弹窗边界裁切，调整高度又容易引起位置跳动。后来改为用户点击后按需注入网页的浮层，通过 Shadow DOM 隔离样式，让候选列表能够越过面板边界。与此同时，还要处理网页快捷键干扰、焦点、关闭与卸载，确保添加面板不会影响原网页操作。

搜索则是另一类挑战。一个输入框背后，同时存在工作台已经生效的条件、搜索面板中正在修改的条件，以及临时打开的详情。如果这些状态直接混在一起，用户只是试着搜一下、看一眼内容，原来的工作台就被改变了。

现在搜索面板允许先调整类型、时间、标签和搜索字段，再预览结果；只有明确选择“查看全部结果”时，才把条件应用到工作台。取消搜索会保留原来的浏览上下文。这里需要反复打磨的，是返回后输入还在不在、列表是否回到原位、Esc 应该先关闭哪一层。这些小地方会直接影响查找过程是否连贯。

AI 整理同样需要明确边界。生成一些标签并不难，难的是避免不断产生近义词，以及保护用户已经做过的修改。我需要记录描述的来源、区分人工和自动结果，并让失败可以重试。否则，自动整理很容易给收藏库带来新的维护工作。

## 思考

Wispora 让我花了很多时间去想：一个收藏工具，怎样才能让保存过的内容再次进入工作。

封面帮助我认出它，描述帮助我想起添加它的原因，标签和搜索帮助我缩小范围，正文快照则保留当时读到的内容。这些能力需要连在一起，收藏才有机会变成真正用得上的积累。

和 Codex 一起开发，也让我能在设计之外，继续验证交互和数据流程。很多问题只有把界面做出来、放进真实浏览场景后才会出现：候选列表被裁切、返回时位置丢失、颜色在不同环境中不一致。设计系统和清晰的产品边界，让这些调整有了可以持续维护的基础。

我想先把这个本地工具用扎实。接下来需要通过真实浏览器和连续使用，验证保存是否可靠、查找是否顺手，以及 AI 到底节省了多少整理时间。等这些问题有了答案，再决定它应该长出哪些新功能。
